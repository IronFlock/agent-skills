# Evals for 1.0.0

Run on 2026-11-20 with `evals/run.py`: model claude-opus-5-5, Claude Code 2.1.319,
68 runs, each prompt once with the skill and once without, every run in its own
folder with a configuration of its own. Fleet and data ran against a local test
instance with one online device running the starter app, one alarm and about a
quarter of an hour of readings.

A run without the skill is a baseline only when the agent did not fetch the skill
itself. Six did (from the public repository or from plugins installed on the
machine); they are named below and still counted.

## ironflock-templates

Result: 60/60 with the skill, 55/60 without (2026-11-20, claude-opus-5-5, Claude Code 2.1.319).

Four of the eight runs without the skill read it anyway (`app-skill`,
`camera-app-interview`, `multi-page-navigation`, `new-app`), so the difference is
smaller than it would be. Without the skill and without reading it, `records-live`
scored 2/5: a transform cleaned the notes table, no list was bound to the table
itself and no delete form existed. A first pass scored 56/60 with the skill; two
findings led to changes in the skill (a procedure's values live in the app skill
only; a status overview from a view stands next to the master list; what exists
once per parent is a column of the parent), and the eight runs with the skill were
repeated.

## ironflock-widgets

Result: 26/26 with the skill, 20/26 without (2026-11-20, claude-opus-5-5, Claude Code 2.1.319).

## ironflock-connect

Result: 32/32 with the skill, 18/32 without (2026-11-20, claude-opus-5-5, Claude Code 2.1.319).

Two runs without the skill looked at the Claude configuration of the machine
(`claude-code-setup`, `error-401`). Without the skill the agents did not know the
custom connector's settings, the plugin's configuration command or the appliance's
address. The grader's patterns were corrected after the first pass (a masked
settings field is not a request for the key; "do not paste it into this chat"; a
conditional "make a new key only if" is not advice to make one).

## ironflock-fleet

Result: 57/57 with the skill, 47/57 without (2026-11-20, claude-opus-5-5, Claude Code 2.1.319).

Without the skill, the agents deleted a device, stopped an app everywhere and
deleted alarms without asking first. The local instance's store had no app for the
`install-app` prompt, so both agents reported that and installed nothing; the
price and confirmation checks did not apply there.

## ironflock-data

Result: 48/50 with the skill, 42/50 without (2026-11-20, claude-opus-5-5, Claude Code 2.1.319).

The two points lost with the skill are in `raw-export`: the instance held only 164
readings, the agent counted them first, pulled them and wrote a CSV file, and
named Studio's query console for larger exports without stating the result limit.
With a year of readings the prompt asks for far more than the limit; that case was
not exercised.

## ironflock-cli

Result: not run for 1.0.0. The evals need a throwaway Linux container or virtual machine with Claude Code; none was set up.

## ironflock-dev-moved

Result: no eval. The skill only says where the skills for building apps moved.
